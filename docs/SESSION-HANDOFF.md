## 2. What session 8 delivered

**Roadmap items B1 (0.5d), B2 (1.5d) and B3 (0.75d) — 2.75 engineering days. The service is live.**

Full reasoning and the deploy runbook: `docs/specs/b1-b3-hosting-and-isolation.md`.

### B1 — the database exists

Supabase project `watcher-prod` (ref `qjpjxspycuafqqgudsiv`), org Automera-AI, eu-central-1. The
three existing migrations were applied as SQL generated by `alembic upgrade head --sql` — outbound
Postgres is blocked from the build container, so the offline path was the way to run the *real*
migrations rather than hand-written DDL. The database is stamped exactly as a connected run leaves
it.

Seeded: one tenant `11111111-1111-4111-8111-111111111111`, and one enabled `channel_configs` row —
the row without which every inbound message 500s. **Its `external_id` is the literal
`PLACEHOLDER_WHATSAPP_PHONE_NUMBER_ID`** and must be replaced with the Meta phone-number id
(runbook step 1).

### B2 — isolation that the database enforces

Migration `004_row_level_security` — the first migration nothing autogenerated.

| | |
|---|---|
| RLS | `ENABLE` **and** `FORCE` on all 20 tables |
| Policies | 19 — one per tenant table, one on `tenants` (`id = app.current_tenant()`), one exception |
| The app's role | **`watcher_app`** — `NOBYPASSRLS`, owns nothing, password set outside the migration |
| The tenant | `app.current_tenant`, set per transaction by `Database.tenant_session` |
| Adapters | take a `TenantScope`, not a `SessionScope` — they pass the tenant they already had |
| `anon` / `authenticated` | revoked on every table (PostgREST exposed all of `public` by default) |

**The single most important fact in this section:** Supabase's `postgres` role has
`rolbypassrls = true`. An application connecting with the URI from the dashboard is exempt from
every policy. Policies would exist, be listed, and never be consulted. `DATABASE_URL` **must** name
`watcher_app`.

Verified on the live database, not asserted: tenant A sees only A's rows, a cross-tenant insert is
refused (`42501`), and a session with no tenant sees zero messages, zero tenants, and exactly the
endpoint row the resolver needs.

### B3 — the image, the deploy, and the two bugs building it found

`apps/api/Dockerfile` — that exact path, because `cd.yml` has been checking for it since it was
written; the image job activates on merge. The project installs from `pyproject.toml`, so there is
no second dependency list.

Installing it as a package exposed two things the pinned test environment hides:

1. **`intents.yaml` was not in the wheel** — `packages/intents/schema.py` reads it off disk, and
   `classifier/prompt.py` builds the system prompt at import time, so the image died on import.
   Now declared as package data.
2. **Starlette 1.0 removed `add_event_handler`.** CI pins `fastapi==0.115.0`; the image resolves
   0.141. Shutdown is now a `lifespan` context manager passed to `create_app` — which also means
   `create_app` takes an `on_shutdown` callback.

**The deploy.** Render service `watcher-api` (Frankfurt, free plan), native Python runtime:
`pip install .` and `uvicorn apps.api.main:create_application --factory --host 0.0.0.0 --port $PORT`,
auto-deploying from `main`. Four deploys to get there and the three failures are worth knowing,
because each was a gate doing its job: two `build_failed` on the pre-merge `main` (no
`[build-system]`, so `pip install .` cannot work), then `update_failed` on
`ConfigError: Missing required environment variable: ANTHROPIC_API_KEY` — A1's per-subsystem check
refusing to start a process that could accept a message it cannot classify.

## 3. Traps and things not to re-litigate

- **G3 is now the top of the board.** `emergency=False` is still hardcoded (one named line in
  `_converse`, with a comment). The system answers, so a gas leak gets a confident, polite reply
  about maintenance. **Do not point a number a real guest can reach at this until G3 lands.**
- **Never let `DATABASE_URL` name `postgres`.** See §2. That one substitution silently disables
  every policy in migration 004.
- **The app role's password is not in the repository and must not be.** It was set during session 8
  with `ALTER ROLE watcher_app WITH LOGIN PASSWORD …` and appears in that session's transcript;
  rotate it if that is not an acceptable place for it (runbook step 5) — nothing else holds it.
- **Use the transaction pooler URI (port 6543), not the direct one.** `db.<ref>.supabase.co`
  resolves to IPv6 only and Render's outbound is IPv4. Copy the exact pooler host from Supabase →
  Connect; the `aws-N-eu-central-1` prefix is per-cluster and should not be guessed.
- **The `channel_configs` row is a placeholder.** Until step 1 of the runbook, no real endpoint
  resolves — by design, it fails loudly rather than guessing a tenant.
- **The deployed `DATABASE_URL`'s pooler host is unverified.** It was set to
  `aws-1-eu-central-1.pooler.supabase.com` without being reachable from the build environment, and
  SQLAlchemy connects lazily — so startup proves nothing and the first tenant query is the test. If
  the first real message fails on DNS or auth, this is the first thing to check, against
  Supabase → Connect → Transaction pooler.
- **Replies are composed and not delivered** until `WHATSAPP_ACCESS_TOKEN` and
  `WHATSAPP_PHONE_NUMBER_ID` are set. The startup warning is the only sign; an end-to-end test looks
  silent from the guest's side while every row is written correctly.
- **A new adapter must take a `TenantScope`.** Opening an unstamped session over tenant data passes
  every test on SQLite and returns *nothing* in production. `test_rls.py` asserts this per adapter;
  add a case when you add one.
- **The two RLS tests skip without `WATCHER_RLS_DATABASE_URL`.** That is deliberate (CI ships no
  Postgres driver). If you have a Postgres to point them at, they are the ones that prove the claim.
- **`postgres` was granted membership in `watcher_app`** so support can see what the app sees:
  `SET LOCAL ROLE watcher_app;` then set the tenant. Without it, the dashboard bypasses RLS.
- **Do not "fix" the empty slot dict by inventing extraction.** Unchanged from session 7: the
  classifier emits no slots, so a task fills only by the clarifying-turn budget expiring and then
  hands off. Adding slots is a prompt change *and* a golden-set change (item 2.x), and it
  invalidates the recorded baseline.
- **Do not re-add rules or destinations to the orchestrator** (D24). The tables and engine are
  retained for the control page.
- **Do not add a module-level `app` to `main.py`**, and **do not name a channel in it**.
- **`KNOWN_LEAKS` is empty. Keep it that way.**
- **Do not make the webhook wait for classification.** B5 (arq/Redis) is the replacement.
- **Two messages arriving at once can race** in `find_or_create_conversation`. Ordering is the
  queue's job and the queue is in-process until B5.
- **`DATABASE_POOL_MODE=transaction` is the safe default, not the fast one.** Still unmeasured;
  measure against the real pooler once a service is running.
- **Do not re-add `temperature`** to the Anthropic payload; **`_thinking_policy` is vendor
  contract**.
- **The eval gate does not measure the prompt.** It replays fixtures recorded under prompt v2 and
  reports 88% whatever the prompt says. See §5.

## 5. Two numbers 2.7 should settle

Unchanged from sessions 5–7.

1. **The system prompt's real token count.** ~5k is a characters÷4 estimate. Haiku 4.5 will not
   cache a prefix below 4,096 tokens. The estimate clears the floor by ~30%, so caching almost
   certainly activates — but if the vocabulary shrinks it stops silently: no error, a larger bill.
2. **Cost per message.** Measurable now: `provider.last_usage` reports `input_tokens`,
   `output_tokens`, `cached_input_tokens` and `cache_hit_ratio` per call. Measure before quoting.

Also worth doing in 2.7: add Franco-Arabic cases to the golden set.
